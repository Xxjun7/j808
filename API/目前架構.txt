目前整體架構可以理解成 **「前台網站 + API 設定檔 + GAS \+ Google Sheet」四層**。

 ## 目前架構

```
┌──────────────────────────────┐
│        使用者手機 / 電腦       │
│                              │
│  金正旺 VIP 查詢前台           │
│  Index.html                  │
│                              │
│  輸入：會號＋貴賓本名          │
└──────────────┬───────────────┘
               │
               │ ① 按「查詢」
               ▼
┌──────────────────────────────┐
│       API 設定檔              │
│                              │
│  /j808/API/J.json            │
│                              │
│  {                           │
│    "apiUrl": "GAS 網址"       │
│  }                           │
└──────────────┬───────────────┘
               │
               │ ② 取得最新 API URL
               ▼
┌──────────────────────────────┐
│       Google Apps Script     │
│                              │
│       doGet(e)               │
│                              │
│  收到 uid                     │
│       ↓                      │
│  找「會員」工作表             │
│       ↓                      │
│  比對 G 欄                    │
│       ↓                      │
│  找到會員                     │
│       ↓                      │
│  取得同列 C 欄點數            │
└──────────────┬───────────────┘
               │
               │ ③ JSON
               ▼
┌──────────────────────────────┐
│       前台 Index.html         │
│                              │
│  解析 JSON                    │
│       ↓                      │
│  顯示會員                     │
│  顯示目前點數                 │
│  顯示查詢時間                 │
│  顯示提醒                     │
└──────────────────────────────┘
```

 ## 一次完整查詢

 現在使用者按一次「查詢」後，流程是：

```
使用者輸入
    ↓
按「查詢」
    ↓
查詢按鈕立即鎖定
    ↓
讀取 J.json
    ↓
取得最新 apiUrl
    ↓
GAS warmup
    ↓
呼叫 GAS
    ↓
GAS 查詢 Google Sheet
    ↓
G 欄比對 UID
    ↓
找到 → 讀 C 欄點數
    ↓
回傳 JSON
    ↓
前台顯示結果
    ↓
查詢完成
    ↓
查詢按鈕解除鎖定
```

 ## 各部分負責的事情

 ### 1\. 前台 `Index.html`

 主要負責：

 - UI
- 使用者輸入
- API 設定讀取
- 發送查詢
- Loading
- 錯誤訊息
- 顯示會員資料
- 顯示點數
- 顯示查詢時間
- 防止連續查詢

 **不直接碰 Google Sheet。**

---

 ### 2\. `J.json`

 這層相當於：

 > **API 地址的設定中心**

 例如：

```
{
  "apiUrl": "你的 GAS Web App URL"
}
```

 目前的設計是：

 > **每次查詢才讀一次 J.json**

 所以前台不需要把 GAS 網址永久寫死在 HTML 裡。

---

 ### 3\. GAS

 GAS 是真正的：

 > **資料查詢後端**

 目前只負責：

```
收到 UID
 ↓
會員!G:G 搜尋
 ↓
找到所在列
 ↓
取得 C 欄
 ↓
JSON 回傳
```

 例如：

```
{
  "success": true,
  "uid": "A001王小明",
  "points": 350
}
```

---

 ### 4\. Google Sheet

 目前是資料來源。

 你的主要欄位邏輯是：

```
會員工作表

C 欄              G 欄
─────             ─────────
點數               UID
350                A001王小明
120                A002陳小華
580                A003林小美
```

 GAS 用 G 欄找到會員後，再拿**同一列的 C 欄**。

---

 ## 目前最重要的特性

 現在這個架構有一個很明確的優點：

 ### API 可以換

 因為前台不是寫死：

```
const API_URL = "某個GAS網址";
```

 而是：

```
Index.html
     ↓
J.json
     ↓
取得 GAS URL
```

 所以未來如果 GAS 部署版本改變，只要更新 `J.json`：

```
舊 GAS
↓
修改 J.json
↓
新 GAS
```

 前台本身不用修改。

 而且按照你現在剛指定的架構：

 > **每次查詢都重新讀 J.json**

 所以不需要重新整理頁面才能取得新的 API 設定。

---

 ## 目前的「查詢鎖定」邏輯

 這部分現在也是完整的：

```
        按查詢
           ↓
     ┌─────────────┐
     │ 按鈕 disabled │
     └──────┬──────┘
            ↓
        API 查詢中
            ↓
      ┌─────┴─────┐
      ↓           ↓
    成功         失敗
      ↓           ↓
      └─────┬─────┘
            ↓
       finally
            ↓
    按鈕重新啟用
```

 因此不會出現：

```
按一下 → GAS Request 1
按一下 → GAS Request 2
按一下 → GAS Request 3
按一下 → GAS Request 4
```

 而是：

```
按一下
 ↓
查詢中 🔒
 ↓
等待結果
 ↓
完成
 ↓
解除 🔓
```

 ### 所以目前我會把你的架構定義成：

 **前台負責介面與請求控制 → J.json 負責 API 路由 → GAS 負責資料查詢 → Google Sheet 負責資料儲存。**

 這個分層是清楚的，而且目前你要求的兩個修改也都已經符合這個架構。
